## 重點新聞

### 1. Agent Plugins 1.0 正式登上 VS Code 與 Copilot，一份 package 可跨 Agent 工具使用

**發生什麼事**

GitHub 在 8 月 12 日宣布，Agent Plugins 1.0 已在 VS Code、Copilot CLI、GitHub Copilot SDK 與 Copilot app 正式可用，涵蓋所有 Copilot 方案。開發者可在同一個 plugin package 中放入操作知識的 Agent Skill 與工具連線的 MCP server，讓相容 client 從相同目錄與 manifest 載入；不必再為 IDE、終端和 Copilot app 各維護一套近似封裝。

Agent Plugins 1.0 規格本身於 8 月 6 日由 AWS、Anysphere、Microsoft、OpenAI、Vercel 共同發布，Google 同日加入核心維護者。本日的合格新發展是 GitHub Copilot 多個 client 已正式支援，而不是把 8 月 6 日規格發布重新改標日期。

**具體進步與限制**

可攜核心以根目錄 `plugin.json` 為入口，skill 放在 `skills/`，MCP 設定放在 `mcp.json`。Copilot 專屬的 custom agents、commands、rules、hooks 與 canvases 則放入 `com.github.copilot/` 命名空間，其他 client 可忽略它，但仍能使用共用的 skill 與 MCP。既有 GitHub Copilot plugins 不必立即遷移，也不會因 1.0 上線而失效。

企業原本使用的 `enabledPlugins`、`extraKnownMarketplaces`、`strictKnownMarketplaces` 與 MCP allowlist 可繼續跨 VS Code、CLI、Copilot app 與 cloud agent 管理插件，不需要另建一套 Agent Plugins policy。這解決的是重複封裝與治理，不代表所有 client 都支援同樣的 UI、hook 或自訂 agent；client-specific 功能仍要逐端測試。

**對工作的影響**

- 前端團隊可把設計系統規範、元件產生器、可及性檢查、測試／部署 runbook 與對應 MCP server 包成一份 plugin，讓工程師在 VS Code、終端與 Copilot app 使用相同版本。
- 遷移可採官方 example 的 additive 做法：先新增並驗證 `plugin.json`，保留目前可用的舊平台檔案，再搬移共用 skill／MCP，最後逐一測試 client extension，避免一次刪掉既有封裝。
- UI/UX 與企業治理介面應顯示 plugin 來源、將啟用的 skill／MCP、client-specific extension 與管理員限制；「一次安裝」不能讓使用者誤以為所有工具權限與行為完全一致。

### 2. Claude Code 2.1.229 補上遠端續接、runner hooks 與動態 plugin 來源

**發生什麼事**

Anthropic 發布 Claude Code 2.1.229。`claude remote-control --continue` 現在有正式說明，可直接接回最近一段 Remote Control session；self-hosted runner session 也能接收伺服器端提供的 Claude Code hooks，行為與 Anthropic managed environment 更一致。Plugin marketplace 新增 `command` source：本機命令或 IDE 可以回傳 plugin 目錄，Claude Code 每次 session 重新解析，不必重啟才能套用變更；`mode: "link"` 可直接使用該目錄。

**具體進步**

長時間思考若透過 Vertex AI 或 Amazon Bedrock gateway 執行，串流現在會送出 SSE keepalive，降低上游 idle timeout 把工作中途斷開的機率。`ListAgents` 會把斷線的 Remote Control session 標成 `offline`，並把自己的雲端 session 標成 `cloud`，跨裝置選擇目標時較不容易誤判狀態。

可靠度修正涵蓋：串流長回覆部分消失或重複列印、Windows extended-length／UNC path crash、極窄終端的 progress bar／Markdown table crash、Claude Code Review workflow 完成卻未在 PR 留下 review、連接 IDE extension 時大量 diagnostics 造成數秒卡頓，以及 self-hosted runner repository preparation 卡在 Git Credential Manager。Workflow fan-out 也會錯開具有相同 prompt prefix 的 sibling agents，讓後續 agent 更可能讀到 prompt cache，而不是重付相同前綴成本。

安全上，`/commit-push-pr` 不再自動核准帶 `--force`、`--amend`、`--no-verify` 等危險旗標的 git／gh 命令；sandbox 對 IPv6 與模糊網路規則改成 fail-closed 並由 `/doctor` 標示。這些修正降低誤執行與斷線風險，但 server hooks、動態 command source、MCP 與 Git 權限仍需管理員明確治理。

**對工作的影響**

- 使用 Windows、Remote Control、自架 runner 或 Claude Code Review 的前端團隊可升級後回歸測試：續接最近 session、長思考串流、UNC／長路徑、server hooks、PR 留言與大型 IDE diagnostics。
- 內部 IDE 或 monorepo 工具可用 `command` source 依目前 workspace 即時決定 plugin 目錄，減少切分支、切專案後手動重啟；仍要驗證命令來源可信、輸出目錄固定在允許範圍，並記錄實際載入版本。
- 多 agent 建置或測試可觀察 prompt cache read 與整體 token，確認 stagger 是否真的降低成本；不能只看代理回報完成，仍要檢查測試產物、Git 狀態與 PR 上是否真的出現 review。

## 對工作流的意義

今天兩則更新都在處理 agent 從單一聊天工具走向可攜、可治理的開發基礎設施。Agent Plugins 1.0 把共用知識與 MCP 工具封裝成可跨 client 的核心，Claude Code 2.1.229 則讓動態 plugin、遠端 session、自架 runner 與多 agent 串流更可續接。對前端團隊而言，下一步是把設計規範、測試與部署流程拆成可攜核心與 client-specific extension，同時保留來源、版本、權限、真實產物與失敗狀態的驗證，不能因為封裝更方便就降低治理標準。
