## 重點新聞

### 1. OpenAI Presence 正式推出，企業語音與聊天 agent 有完整治理與改進流程

OpenAI 推出 Presence，讓企業把客服、銷售或內部支援 agent 接到公司知識與系統，依政策執行核准動作，遇到高風險或超出範圍的情況再轉交真人。它已透過限量正式供應計畫提供給符合資格的企業客戶，但由 OpenAI 工程師與指定整合商協助部署，尚不是一般團隊可自行開通的產品。

- 具體進步：Presence 把政策與標準作業程序、權限、guardrails、模擬測試、評分、真人接手和上線後監測整合在同一流程；Codex 可根據真實對話與升級紀錄提出修改，團隊先與正式版本比較測試，再核准分批更新。OpenAI 表示自家英文電話支援已能在不轉真人的情況下解決 75% 來電，且改進迴圈在 10 天內把真人接手比例降低 15 個百分點；這些數字仍屬官方自述。
- 工作影響：前端與 UI/UX 團隊若設計客服或內部服務入口，應把身分驗證、agent 正在使用的資料、即將執行的動作、需人工核准的節點、轉接狀態與稽核紀錄做成清楚介面，而不是只放一個聊天框。一般開發者仍可用 Agents SDK 與 Realtime API 自建語音原型，但 Presence 的受管部署需要透過 OpenAI 客戶團隊評估。
- 當日官方來源：[OpenAI：Introducing OpenAI Presence](https://openai.com/index/introducing-openai-presence/)
- 實作參考：[OpenAI Agents SDK：Voice Agents Quickstart](https://openai.github.io/openai-agents-js/guides/voice-agents/quickstart/)

### 2. GitHub Copilot 新儀表板把使用者分成三個採用階段，不再只看活躍人數

GitHub 為企業管理員與組織擁有者推出 Copilot impact dashboard，依最近 28 天的實際功能使用，把已參與的使用者分成 Code-first、Agent-first、Multi-agent／Copilot app 三個階段，並另外標示已授權但未投入使用的人。每個階段可查看人數、占比、每人每月合併 PR、PR 合併速度中位數與每日程式碼行數。

- 具體進步：管理者現在可把六個月的採用階段變化、PR 吞吐與合併速度放在同一畫面比較，並取得讓團隊進入下一階段的建議，不必只用席次或活躍人數猜測 Copilot 是否真正進入工作流。儀表板沿用 usage metrics API 的 `ai_adoption_phase` 分類，因此能與既有 API、匯出資料和 repo 指標交叉分析。
- 工作影響：前端主管可先找出只用補全、已使用 agent、以及開始跑多 agent 的團隊，再針對不同階段安排訓練、repo 規則與成本預算；評估時仍要一起看測試通過率、缺陷、review 時間、回滾與人工修正，不能把程式碼行數或 PR 速度直接當成品質或因果證明。資料也可能受 IDE telemetry、組織歸屬與兩天處理延遲影響。
- 當日官方來源：[GitHub Changelog：New Copilot usage metrics impact dashboard](https://github.blog/changelog/2026-07-22-new-copilot-usage-metrics-impact-dashboard/)
- 操作參考：[GitHub Docs：GitHub Copilot usage metrics](https://docs.github.com/en/copilot/concepts/copilot-usage-metrics/copilot-metrics)
- 欄位參考：[GitHub Docs：Data available in Copilot usage metrics](https://docs.github.com/en/copilot/reference/copilot-usage-metrics/copilot-usage-metrics)

### 3. OpenAI 公開新聞組織案例：AI 已進入查證、CMS、翻譯與互動閱讀

OpenAI 整理多家新聞組織已在運作的 AI 工作流：AP 用於掃描資料、追查影像來源與整理法院文件，新聞室把公開會議與歷史資料變成可搜尋內容，也有媒體製作文章語音、雙語版本、個人化摘要、自然語言餐廳搜尋和可與角色對話的互動故事。這是正式案例整理，不是新的模型或平台功能發布。

- 具體進步：案例顯示新聞 AI 已從單次摘要延伸成有來源、有編輯規則與人工把關的完整產品流程：先整理大量文件或影音，再把結果送進 CMS、搜尋、翻譯、語音與互動閱讀介面。對產品團隊而言，可直接參考的重點是保留引用、時間與地點線索、內容權利和編輯核准，而不是讓模型自行發布。
- 工作影響：前端與 UI/UX 團隊可把可信內容庫做成可追問的搜尋、在文章中加入來源卡、時間線、地圖、音訊與後續問題模組，並讓使用者看得出哪些內容由 AI 協助、依據哪些原文、何時經人工確認。平面與內容設計可用同一批已核准素材產生多語與多格式版本，但仍要處理著作權、品牌語氣、錯誤更正和無障礙。
- 當日官方來源與案例：[OpenAI：How news organizations are using AI to advance their vital missions](https://openai.com/index/how-news-organizations-are-using-ai/)

## 對工作流的意義

今天三則消息的共同點不是模型又多一個按鈕，而是 AI 進入正式工作流後，產品必須同時回答「能做什麼、依據什麼、誰能核准、何時轉交真人、如何驗證成效」。前端與設計團隊可以先把來源、權限、動作確認、人工接手與錯誤更正設計成一級介面，再用測試、缺陷、人工修正和真實任務成功率評估價值；只有速度或產出數量，無法證明工作真的變好。
