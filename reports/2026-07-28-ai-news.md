# 2026-07-28 AI 每日新聞

## 今日摘要

2026-07-28 整理 1 則值得追蹤的 AI 開發更新：Model Context Protocol 正式發布 2026-07-28 規格，把 MCP 改成更容易水平擴充的無狀態架構，並讓工具能在執行途中安全地向使用者補問或取得核准；官方 TypeScript、Python、Go 與 C# SDK 已同步支援。

## 重點新聞

### 1. MCP 正式改為無狀態架構，AI 工具更容易擴充、快取與插入人工核准

Model Context Protocol 正式發布 2026-07-28 規格。MCP server 不再必須替每個連線保存 session；每次請求會自行帶齊版本、client 身分與能力，因此可交給一般負載平衡器分派。工具若執行到一半需要補參數或請使用者確認，也能用 Multi Round-Trip Requests 暫停並帶著回答重試，不必維持長時間雙向連線。

- 具體進步：無狀態核心降低 serverless、edge 與多節點部署的共享狀態負擔；method／tool 可由 `Mcp-Method`、`Mcp-Name` HTTP header 路由和計量，工具、prompt 與 resource 清單也能帶快取提示，減少重抓與 prompt cache 波動。新版同時強化 OAuth issuer 驗證與 credential 隔離，建立正式 extension 與至少 12 個月的棄用窗口。
- 人工核准流程：Multi Round-Trip Requests 讓 server 在工具執行中回傳 `input_required`，client 收集使用者回答後重試原呼叫。這適合缺參數、付費、發布、刪除或其他需要中途確認的操作，也讓介面能在不維持雙向 stream 的情況下保留清楚的核准節點。
- 工作影響：前端與 agent 團隊可把 Figma、GitHub、CMS、設計系統或內部資料工具部署到 Cloudflare Workers、Netlify Functions 等可水平擴充環境，不必另外維護黏著 session。UI/UX 應顯示工具正在等待什麼、會執行什麼動作、成本或資料範圍，以及使用者接受或拒絕後會發生什麼。
- 遷移注意：TypeScript、Python、Go 與 C# Tier 1 SDK 已支援新規格，但依賴 `initialize`、`Mcp-Session-Id`、舊 sampling／logging／roots 或 server 主動呼叫 client 的實作需要調整。既有 client／server 不必在同一天硬切，官方提供版本協商、遷移指南與 conformance tests，可先在 CI 同時驗證新版與相容路徑。

## 選題說明

7 月 23 日曾收錄 GitHub MCP Server 對新版規格的提前支援；本次收錄的是 7 月 28 日正式發布的協定、Tier 1 SDK 與遷移路徑，屬公開可用的實質新發展，不是重複報導。

其餘指定官方來源未見同日且更直接影響前端、UI/UX、網頁或平面設計工作流的正式 AI 產品發布。GitHub 當日兩則供應鏈安全改善不是 AI 功能；Meta 簽署歐盟 AI 生成內容透明度行為準則屬政策承諾，沒有同日產品能力變更；Windows 11 預覽更新中的 Ask Copilot 與多語音輸入屬漸進推出的小幅系統功能，因此不為增加篇數而納入。

## 對工作流的意義

這次更新把 MCP 從需要維持連線狀態的特殊整合，往一般 web 基礎設施熟悉的無狀態、可路由、可快取模式推進。對前端與設計工具團隊，最值得先做的不是全面升級，而是挑一個真實 MCP server：列出 session 與舊 API 依賴，把刪除或付費等高風險動作改成明確的中途核准，再用官方測試套件確認新舊 client 都能安全工作。
