# 2026-08-06 AI 每日新聞

## 今日摘要

本日收錄 2 則官方消息。Claude Code 2.1.223 修補多個會讓權限檢查、核准畫面與 workflow sandbox 失真的漏洞，並讓企業外掛政策可直接套用整個 GitHub 組織；ChatGPT 則更新 GPT-5.6 Sol 的回答品質與思考量控制，Free／Go 方案也將陸續改用 Luna 並取得 Think 按鈕。排名優先考量已正式發布、會直接影響 AI coding 安全與日常前端／設計工作流的變化。

## 重點新聞

### 1. Claude Code 2.1.223 封住隱藏指令與工作流 sandbox 缺口，企業外掛政策也能整個 GitHub 組織套用

**發生什麼事**

Anthropic 在 8 月 6 日發布 Claude Code 2.1.223。安全修正包括：惡意 Bash 指令不能再把部分內容藏過權限檢查；以 tab 或不可見 Unicode 填充的命令不能再讓核准視窗漏掉實際內容；workflow script 不能再用動態 `import()` 跑到 sandbox 外；agent definition 的 `bypassPermissions` 也不能再忽略企業已設定的禁用政策。

管理面同時新增 GitHub 組織萬用字元。企業可在 `strictKnownMarketplaces` 或 `blockedMarketplaces` 使用 `"owner/*"`，一次允許或封鎖該組織下的所有 marketplace repository，不必逐一維護 repo 清單。

**具體進步**

使用者在核准工具時，畫面現在更接近實際要執行的完整命令；企業禁用跳過權限後，個別 agent 設定也不能自行放寬。這降低了不可見字元、命令解析差異與工作流程式載入造成的越界風險。組織萬用字元則把大量 repository 的政策維護收斂成一條規則，但仍需確認該組織本身的外掛治理可信。

**對工作的影響**

- 使用 Claude Code 跑套件安裝、建置、Git 或多代理任務的前端團隊應先更新，再用含 tab、不可見字元與動態 `import()` 的測試案例重跑權限檢查。
- 企業管理員可用 `owner/*` 管理公司內部外掛，仍應搭配最小權限、sandbox、版本控制與明確的外掛審核責任。
- UI/UX 團隊可把這次修正當作權限介面原則：核准畫面必須顯示完整實際動作，不能只給容易被裁切、折疊或藏字的摘要。

**日期證據：** 官方 changelog 的 2.1.223 節明確標示「August 6, 2026」。

**產品狀態：** 已正式發布。

**官方來源：** [Anthropic Claude Code Changelog](https://code.claude.com/docs/en/changelog)

**官方實作參考：** [Claude Code：Create and distribute a plugin marketplace](https://code.claude.com/docs/en/plugin-marketplaces)、[Configure permissions](https://code.claude.com/docs/en/permissions)

### 2. ChatGPT 更新 GPT-5.6 Sol 並加入思考量滑桿，Free／Go 將改用 Luna 與 Think 按鈕

**發生什麼事**

OpenAI 在 8 月 6 日更新 ChatGPT：Plus 與 Pro 使用者現在會使用新版 GPT-5.6 Sol，官方表示事實回答更可靠、內容更聚焦，並在介面加入滑桿，讓使用者直接選擇回答要投入多少思考。

Free 與 Go 會在本週把 GPT-5.6 Luna 設為預設模型；從下週起，這兩個方案也會取得不限次數的文字聊天與 Think 按鈕，但仍受濫用防護限制，檔案上傳、圖片與其他工具也繼續有額度。這次只改 ChatGPT 對話體驗，Work 與 Codex 沒有同步改動。

**具體進步**

需要快速草稿或深入推理時，使用者可在同一介面調整思考量，不必只靠改寫 prompt 猜測模型要投入多少推理。Free／Go 的日常對話會由較快速的 Luna 處理，遇到較難的問題再主動按 Think。官方尚未提供這次品質提升的量化 benchmark，因此「更可靠」不等於每次都正確，重要內容仍需查證。

**對工作的影響**

- 前端、UI/UX 與設計工作可把低思考量用於文案變體、元件命名與快速整理，把較高思考量留給資訊架構、可及性檢查、複雜除錯與需求衝突分析。
- 團隊應重新抽查既有提示與產出品質，因底層模型更新可能改變語氣、細節與長度；需要穩定格式的流程仍應保留範例、schema 與驗證。
- 產品設計可參考 Think 按鈕與滑桿，把速度／深度做成使用者看得懂的漸進式控制，而不是暴露模型與推理術語。

**日期證據：** ChatGPT Release Notes 以「August 6, 2026」列出本項更新。

**產品狀態：** Plus／Pro 的新版 Sol 與思考量控制已發布；Free／Go 的 Luna 預設與 Think 按鈕為分階段推出。

**官方來源：** [OpenAI ChatGPT Release Notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)

## 對工作流的意義

今天兩則更新都把「使用者實際看見的控制」拉回核心：AI coding 的核准畫面必須忠實顯示真正要執行的命令，ChatGPT 則把思考深度變成可直接調整的介面。對前端與 UI/UX 而言，模型能力之外，更值得檢查的是權限邊界、漸進式控制、狀態說明與驗證流程是否讓人做出正確判斷。
