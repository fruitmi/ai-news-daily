## 重點新聞

### 1. Gemini 3.7 Flash 進入 GitHub Copilot，強化網頁、App 開發與複雜任務驗證

**發生什麼事**

GitHub 在 8 月 13 日開始把 Google 最新的 Gemini 3.7 Flash 帶進 Copilot。Copilot Pro、Pro+、Max、Business 與 Enterprise 使用者可在 VS Code、Visual Studio、Copilot CLI、cloud agent、Copilot app、JetBrains、Xcode 與 Eclipse 選用。GitHub 支援文件已把 3.7 Flash 列為 GA，但實際 rollout 仍是漸進式。

**具體進步與限制**

GitHub 的早期測試顯示，相較前一版，3.7 Flash 在網頁／App 開發、代理式 coding、程式品質、最終輸出呈現、codebase 研究與複雜任務驗證上都有改善。這是供應商端的早期測試，不是所有 framework 與 repository 都會得到相同比例的保證。

VS Code 至少需 v1.128.0，Visual Studio 至少需 17.14.22 或 18.1.0；其他 IDE 的最低版本仍有 TBD 項目。Business／Enterprise 管理員也要先啟用 Gemini 3.7 Flash 模型政策，成員才會看到模型。

**對工作的影響**

- 前端團隊可用真實功能 issue 比較 3.6 與 3.7 Flash 的首次可用率、測試通過率、UI 細節遵循、code review 問題數與人工修正時間。
- 模型適合先放進高頻的元件實作、codebase 研究與測試修正，再以較強模型或人工處理高風險架構決策。
- 模型選擇介面要顯示 client 版本、管理員政策、rollout 狀態與實際驗證結果，不能只顯示「最新」就假設所有人可用。

**日期證據：** GitHub Changelog 頁面明確標示「August 13, 2026」。

**產品狀態：** GitHub Docs 列為 GA；各 client 採漸進推出，Business／Enterprise 受管理員政策控制。

**官方來源：** [GitHub Changelog：Gemini 3.7 Flash is now available in GitHub Copilot](https://github.blog/changelog/2026-08-13-gemini-3-7-flash-is-now-available-in-github-copilot)

**官方使用參考：** [GitHub Docs：Supported AI models in GitHub Copilot](https://docs.github.com/en/copilot/reference/ai-models/supported-models)

### 2. Claude Code 2.1.232 預設開啟 fork 子代理，也補強跨 session、GitLab 與 Windows 權限

**發生什麼事**

Anthropic 發布 Claude Code 2.1.232。Fork 型子代理現在預設啟用：以 `subagent_type: "fork"` 啟動的代理會繼承完整對話與 prompt cache，互動式 session 的非 teammate agent 也預設在背景執行。使用者可在 prompt 輸入 `@` 找到另一個 Claude session，名稱只對應一個 live session 時，`SendMessage` 能直接送達，不必先確認 ref。

同日的 2.1.231 修正 MCP OAuth 連到預先註冊 client（例如 Slack）時，redirect URI mismatch 導致登入失敗的問題，因此與 2.1.232 合併成同一版本事件。

**具體進步**

多代理旁支不必重新貼完整脈絡，跨 session 也新增對話到期、接收／暫存／拒絕設定與唯一命名，較適合把實作、測試和 review 並行。新版同時支援 GitLab plugin marketplace、遮罩多組 GitLab token，並修正：

- PowerShell 參數可無聲覆寫 `$PSDefaultParameterValues`，讓後續指令改走不同檔案路徑。
- Git Bash 透過 Cygwin symlink 寫檔時，path validation 把它誤判成一般檔案。
- 巢狀 Git repository 沿用父層 trust；現在每個 repository 都要自行確認。
- MCP protocol probe 失敗仍卡滿 30 秒、Remote Control 歷史／憑證繼承、idle session 不可達與橋接重啟後歷史消失。
- 遠端斷線後可持續重連約 30 分鐘，且終端會說明 session 是被其他裝置接管、結束或刪除。

**對工作的影響**

- 前端團隊可讓 fork 分別跑實作、測試與 code review，主 session 保留協調；仍要限制同時工作數並檢查每個 diff、測試與權限。
- Windows、GitLab、MCP 或 Remote Control 使用者應回歸測試 PowerShell 參數、symlink 寫入、nested repo trust、OAuth、斷線重連與 token 遮罩。
- UI/UX 可參考跨 session 的接收／暫存／拒絕、唯一命名與明確終止原因，避免背景代理只用模糊的「完成／離線」狀態。

**日期證據：** Claude Code Changelog 的 2.1.231 與 2.1.232 均標示「August 13, 2026」。

**產品狀態：** 已正式發布。

**官方來源：** [Anthropic Claude Code Changelog](https://code.claude.com/docs/en/changelog)

**官方使用參考：** [Claude Code Docs：Create custom subagents](https://code.claude.com/docs/en/sub-agents)

### 3. ChatGPT Library 直接接上 Google Drive，資料夾與 Workspace 檔案可邊看邊處理

**發生什麼事**

已連接 Google Drive plugin 的使用者，現在可在 ChatGPT Library 直接瀏覽 My Drive 與別人直接分享的檔案、資料夾；也能從 composer 或 `@mention` 把 Drive 檔加入 Chat 或 Work，不必先下載再重新上傳。

處理檔案時，Google Docs、Sheets 與 Slides 可開在對話旁邊，使用者可要求摘要、比較、建立新內容或處理整個資料夾；在支援且已授權的情況下，ChatGPT 也能更新來源檔。

**具體進步與限制**

檔案保留與 Drive 的連結，能直接回到原始位置檢查，減少下載、重傳與多份副本造成的版本分叉。首波只含 My Drive 與直接分享項目，不含 Shared Drives；部分編輯與協作能力尚未支援。功能正在 web 的 Chat／Work 逐步推出給 Plus、Pro、Enterprise、Edu、Healthcare 與 Business，行動版稍後加入。

Google Drive action 仍沿用原系統與 ChatGPT workspace 權限；讀取、更新、分享或刪除可能需要不同 OAuth scope。管理員應先限定必要 action 與資料夾，再逐步擴大。

**對工作的影響**

- 前端、UI/UX 與設計團隊可直接選 PRD、研究資料夾、品牌規範或活動素材，要求整理驗收條件、比較版本或產生待辦。
- 真正寫回來源前要看清楚檔名、位置、權限與 diff；不能因檔案在對話旁邊開著，就省略版本確認。
- 介面可參考「來源檔保持開啟＋對話處理＋明確寫回」的三欄流程，並為 Shared Drive 缺席、權限不足、同步延遲與外部共用檔提供狀態。

**日期證據：** ChatGPT Release Notes 以「August 13, 2026」列出 Google Drive is now in Library。

**產品狀態：** 正式推出並分階段上線；受方案、web surface、plugin 連線與 workspace 權限限制。

**官方來源：** [OpenAI ChatGPT Release Notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)

**官方使用與權限參考：** [Google App for ChatGPT – Data Controls FAQ](https://help.openai.com/en/articles/10408842)、[Google Drive app with sync - Self-Service Setup](https://help.openai.com/en/articles/10948259-google-drive-synced-connectors-self-service-setup/)

### 4. ChatGPT macOS 加入 Computer History，可選擇讓 ChatGPT、Codex 延續 App 與網站活動脈絡

**發生什麼事**

ChatGPT macOS app 新增可選的 Computer History。ChatGPT 與 Codex 可參考使用者指定 App 與網站的互動事件，回到工作時少重述近期脈絡。它不記錄螢幕截圖、錄影、麥克風或系統音訊，也不包含私人瀏覽。

**具體進步與限制**

使用者可選擇納入哪些 App／網站、暫停紀錄、檢視或刪除 timeline 項目；功能預設關閉。Computer History 目前限 Pro、Business 與 Enterprise，企業成員還要先由管理員授權；EEA、英國與瑞士暫不提供。

它記錄的是 interaction events，不是完整畫面或檔案版本，因此只能用來協助找回脈絡，不能當成設計變更、程式修改或決策的唯一證據。

**對工作的影響**

- macOS 前端與設計工作者可在 IDE、瀏覽器、設計工具與文件間切換後，讓 Codex 或 ChatGPT 接回近期工作線索。
- 重要結論仍要連回實際檔案、URL、diff、Figma／設計稿版本與測試結果。
- 導入時可先只開啟必要 App／網站，確認暫停、刪除、私人瀏覽排除與管理員政策都清楚可控。

**日期證據：** ChatGPT Release Notes 以「August 13, 2026」列出 Computer History for macOS。

**產品狀態：** 已推出但預設關閉；受方案、管理員授權與地區限制。

**官方來源：** [OpenAI ChatGPT Release Notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)

## 對工作流的意義

今天的共同主線是「把分散的工作脈絡直接帶進代理，但仍保留來源與權限」。Gemini 3.7 Flash 擴大可選的 coding 模型；Claude Code 讓同一段脈絡更容易分給背景 fork 與其他 session；Google Drive Library 和 Computer History 則分別把文件與近期活動接進 ChatGPT／Codex。對前端與設計團隊而言，真正要驗證的不只是模型是否更聰明，而是 client 版本、管理員政策、檔案權限、代理 diff、真實測試與可刪除的活動紀錄是否都能被看見。
