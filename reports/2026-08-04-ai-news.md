# 2026-08-04 AI 每日新聞

## 今日摘要

本日收錄 4 則官方消息。Claude Code 同日推出開發介面與隔離安全更新；OpenAI 為教育場景推出三款可直接使用的 Work／Codex plugins，並讓 ChatGPT 所有方案都能把超過 10,000 字元的貼上內容自動轉成附件；GitHub 則正式啟動 github.com 版 Spark 的退場流程。排名優先考量已可用、對 AI coding 與前端工作流的直接影響，以及使用者是否需要立即採取行動。

## 重點新聞

### 1. Claude Code 更新 Focus view，也補上 worktree、背景代理與權限檢查漏洞

**發生什麼事**

Anthropic 在 8 月 4 日連續發布 Claude Code 2.1.221 與 2.1.222。VS Code 新增 Focus view，可把密集的工具活動收進每回合的摘要，同時保留目前執行工具的狀態；安全面則修正隔離 worktree 與其中的 subagent 仍能對主 checkout 執行破壞性 Git 指令、背景代理的 `PreToolUse` auto-allow hook 可繞過工具限制，以及 PowerShell 路徑含引號時的權限判斷問題。

**具體進步**

長任務的畫面不再被每一筆工具紀錄淹沒，使用者仍能展開細節確認代理做過什麼。更重要的是，worktree 的隔離現在同時涵蓋檔案編輯與 Bash；跨 agent 的 `SendMessage` 也會先通過 permission classifier。這些修正降低背景或平行代理越界碰觸主工作目錄的風險，但不代表可以省略版本控制、權限核准與工作樹檢查。

**對工作的影響**

- 前端工程師可用 Focus view 追蹤長時間 refactor、測試或多步驟建置，畫面更容易判讀，必要時再展開工具細節。
- 使用 worktree 或 subagent 平行改程式的團隊應更新 Claude Code，並重新驗證主 checkout 不會被背景任務寫入。
- Windows 團隊遇到特殊字元路徑時，權限檢查會更保守；既有自動化若依賴不跳提示的行為，應重新跑一次。
- UI/UX 可把 Focus view 當作 agent 介面的參考：預設呈現任務進度與摘要，保留可展開的操作證據，而不是在主畫面傾倒完整 log。

**日期證據：** 官方 changelog 在 2.1.221 與 2.1.222 兩節都標示「August 4, 2026」。

**產品狀態：** 已正式發布；屬現有 Claude Code 的功能與安全修正。

**官方來源：** [Anthropic Claude Code changelog](https://code.claude.com/docs/en/changelog)

### 2. OpenAI 推出三款教育 plugins，把課程資料、工具與常用流程直接帶進 Work 與 Codex

**發生什麼事**

OpenAI 推出 K–12 Educator、College Educator 與 College Student 三款教育 plugins。它們把角色專用 skills、指令、apps 與常見流程包在一起，並可連接使用者選擇的文件、教材、日曆及學校核准 apps，讓教師與學生不必每次重建背景資訊或自己組出複雜 prompt。

官方列出的實際用途包括製作差異化教材、互動視覺、測驗、課程海報、可匯入 LMS 的內容，以及依課程來源生成讀書計畫、flashcards、互動教學網站和視覺化解說。

**具體進步**

這不是單一 prompt 範本，而是把資料來源、工具權限與一組可重複執行的教學工作流放進受學校管理的環境。教師與學生能從既有教材開始工作，少做複製貼上與上下文設定；學校仍可決定哪些 apps、資料與 agent 動作可以使用。

**對工作的影響**

- 前端與網頁設計工作可用它快速把課程內容變成互動教學頁、視覺教材或多媒體評量，再由設計者檢查資訊層級、行動版與可及性。
- UI/UX 團隊可參考「角色專用 plugin」做法：讓不同使用者從已配置的資料、工具和流程開始，而不是面對空白聊天框。
- 平面設計師可由課程內容先產生海報、圖解與教材版型草稿，但品牌、版權、學術正確性與印刷規格仍需人工確認。
- 目前不是一般 ChatGPT 個人方案全面開放；導入前需確認學校是否使用 ChatGPT Edu 或 ChatGPT for Teachers 的 district deployment。

**日期證據：** OpenAI 產品頁標示「August 4, 2026」。

**產品狀態：** 已提供給 ChatGPT Edu 與 ChatGPT for Teachers 的 district deployments；屬特定教育方案可用，並非所有 ChatGPT 使用者皆可取得。

**官方來源與案例：** [OpenAI：New ways to learn and teach with ChatGPT Work and Codex](https://openai.com/index/learn-teach-chatgpt-work-codex/)

### 3. GitHub Spark 啟動退場：8 月 4 日停止新建 App，既有使用者須在月底前匯出

**發生什麼事**

GitHub 宣布 github.com 上的 Spark 自 8 月 4 日起不再接受新使用者，也不能建立新的 App。既有使用者可使用到 8 月 31 日，期間應透過「Create repository」把 App 匯出成 GitHub repository。已部署的 App 會在 Spark 退場後繼續運作，但月底後不能再回到 Spark 編輯。

此外，Spark 原本使用的 GitHub Models 已在 7 月 30 日退役，因此 App 內的 `llm()` 呼叫已無法工作。需要 AI 推論的 App 必須改接其他 provider，並自行處理 API key 與計費。

**具體變化與遷移重點**

這不是能力升級，而是正式退場與遷移期限。好消息是程式碼可以匯出，既有部署也不會因 Spark 介面關閉而自動下線；但匯出只保留可接手開發的基礎，AI 呼叫、部署、密鑰、計費與後續維護仍要由團隊接管。

**對工作的影響**

- 曾用 Spark 做活動頁、內部工具或 AI App 原型的團隊，應立即盤點並在 8 月 31 日前匯出，不要只確認公開網址仍能開啟。
- 前端工程師需搜尋 `llm()`、替換推論服務，並把 API key 放在安全的伺服器或平台 secret，不能移到瀏覽器端。
- UI/UX 與設計端應保留流程、文案、素材與互動規格，並在新環境重測登入、資料保存、錯誤狀態、行動版與可及性。
- 已部署 App 雖可繼續運作，仍應建立可維護的 repository、部署流程與負責人，避免月底後只剩無法修改的成品。

**日期證據：** GitHub Changelog 頁面標示「August 4, 2026」，且公告明確寫出當日停止新使用者與新 App。

**產品狀態：** 已正式進入退場；8 月 4 日停止新增，8 月 31 日是既有使用者最後匯出與編輯期限。

**官方來源：** [GitHub Changelog：Upcoming deprecation of GitHub Spark on github.com](https://github.blog/changelog/2026-08-04-upcoming-deprecation-of-github-spark-on-github-com/)

### 4. ChatGPT 長貼文自動轉附件擴及所有方案，避免輸入框與上下文被一次塞滿

**發生什麼事**

ChatGPT Enterprise 與 Education 使用者現在把超過 10,000 字元的內容貼進輸入框時，系統會自動改成附件，而不是直接塞入文字欄位。其他方案先前已具備此功能，因此 8 月 4 日的更新代表這套處理方式已覆蓋所有方案。使用者仍可按「Show in text field」把附件內容轉回直接貼文。

**具體進步**

長程式碼、逐字稿、規格或研究資料不再把 composer 撐成難以編輯的巨型文字區，也能避免一次貼上直接佔滿整個 context window。它改善的是輸入與上下文管理，不等於附件內容一定會被完整理解；重要文件仍應拆段、說明要看的範圍，並檢查回覆是否引用正確內容。

**對工作的影響**

- 前端工程師貼入大型 log、HTML 或元件檔時，輸入區更乾淨，也較容易繼續補充任務要求。
- UI/UX、網頁與平面設計師可把長版需求、訪談逐字稿或品牌規範作為附件，再要求 AI 針對指定章節整理。
- 團隊可減少手動把長文件切成多則訊息，但仍要標出優先順序、限制與輸出格式，避免 AI 對整份附件做錯誤假設。

**日期證據：** ChatGPT Release Notes 以「August 4th, 2026」列出本項更新。

**產品狀態：** 已正式提供；8 月 4 日擴及 Enterprise 與 Education 後，所有 ChatGPT 方案皆可使用。

**官方來源：** [OpenAI Help Center：ChatGPT Release Notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)

## 對工作流的意義

今天最值得處理的是兩件事：先更新會碰程式碼與權限的 agent 工具，再盤點即將失去編輯入口的 Spark App。教育 plugins 與長貼文附件化則顯示產品正把「資料、工具、權限和常用流程」包成更容易開始的工作環境。對前端與 UI/UX 而言，好的 agent 介面不只要會產出內容，還必須清楚呈現進度、保留可展開證據、限制工具權限，並讓資料與舊平台都能被安全接手。
