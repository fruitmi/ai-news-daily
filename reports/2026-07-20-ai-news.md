## 重點新聞

### 1. Ray 2.55 讓同一套分散式 Python 工作流正式跑在 Google Cloud TPU

已用 Ray 在 GPU 上分散執行 Python 的團隊，現在可改用 Google Cloud TPU，而不必另寫一套排程邏輯。Ray 2.55 把 TPU 納入正式發布流程，提供官方預建映像，並讓 Ray Core、Ray Train、Ray Data 與 Ray Serve 沿用既有 task、actor 和部署方式。

- 具體進步：TPU 支援從需要自行建容器、依賴社群協助的實驗路徑，升級成正式 API 與預建映像。GKE 會替同一個 TPU slice 的主機加上標記，Ray 再以 `slice_placement_group()` 一次保留完整拓撲，減少 worker 被拆到不同主機後卡住，以及手寫 placement code 的工作。
- 工作影響：若前端團隊同時維護 AI 搜尋、視覺素材批次處理、RAG、agent 或內部模型服務，可用現有 Ray 程式碼在 GKE 上測試 TPU 訓練與推論，不必為新加速器重做整套分散式架構；一般網站專案不會直接受益，較適合已有雲端 AI 基礎設施與成本／吞吐量需求的團隊。

## 對工作流的意義

這次更新的價值不是讓一般前端頁面直接變快，而是降低自建 AI 服務切換加速器的工程成本。已使用 Ray 的產品團隊，可以保留原有 Python 任務、訓練與服務介面，把評估重點放在 TPU 的吞吐量、成本、模型相容性與 GKE 維運；尚未有分散式 AI 工作負載的團隊則不需要只為追新功能導入這套基礎設施。
