### 1. Google Slides 可直接錄成 Vids，逐字稿剪輯、AI 配音與分享串成一條流程

**發生什麼事**

Google 在 Slides 右側選單加入 `Record`，選取後可直接進入 Google Vids 的錄製流程，並輸出可立即分享的連結。除了錄製簡報，Vids 還提供依逐字稿剪輯內容與生成配音，讓既有 deck 更快變成非同步展示、教學或提案影片。

**具體進步與限制**

以往從簡報到影片常要先匯出素材、另開螢幕錄影或剪輯工具，再手動對齊講稿與畫面；現在流程從 Slides 起點就連到 Vids，講錯的段落可透過逐字稿調整，無法重新錄音時也能用生成配音補上。

Rapid Release 已自 8 月 20 日開始漸進推出，可能需 15 天才看得到；Scheduled Release 預計 9 月 7 日開始。所有 Workspace 客戶、Workspace Individual 與個人 Google 帳號都在供應範圍內，但實際出現時間仍受 rollout 影響。原有的 Slides 錄製體驗暫時保留，入口移到 `View > Slides Recording`。

**對工作的影響**

- 網頁與 UI/UX 團隊可把 prototype walkthrough、design review、元件使用說明或研究發表直接做成可分享影片，減少錄製、剪輯與交接工具切換。
- 平面與品牌設計師可把活動提案、品牌規範或版型簡報轉成有旁白的非同步內容，再以 Vids 協作調整。
- 正式發布前仍要逐段檢查字幕、AI 配音發音、動畫與影片素材是否正確，並補上字幕、逐字稿與必要的無障礙替代內容。

**日期證據：** Google Workspace Updates 原文標示「August 20, 2026」。

**產品狀態：** 已開始推出；Rapid Release 漸進 rollout，Scheduled Release 自 9 月 7 日開始。

**官方來源：** [Google Workspace Updates：Record presentations in Google Slides with Google Vids](https://workspaceupdates.googleblog.com/2026/08/record-presentations-in-google-slides-with-Google-Vids.html)

**官方使用參考：** [Google Workspace Learning Center：Best practices for Google Vids](https://support.google.com/a/users/answer/15599399?hl=en)

### 2. Claude Code 2.1.238 強化長 Session、私有 Plugin 與 Remote Control

**發生什麼事**

Claude Code 2.1.238 針對長時間 coding agent、企業 plugin 分發與自架 runner 補上多項控制。長互動 session 現在會釋放已離開近期顯示範圍的子代理工具結果，避免記憶體無上限成長；私有 plugin marketplace 可透過 `headersHelper` 在抓取 catalog 或同源壓縮檔前取得短效 HTTP header，安裝與更新前會顯示命令並要求 `[y/N]` 確認。

同一版本也新增 self-hosted runner 的延後關機上限，以及每次連線動態取得 `Proxy-Authorization` 的命令／檔案設定。前一個同日版本 2.1.237 則新增內建 `Concise` 輸出風格，並修正透過 LLM gateway 或自訂 base URL 時的 prompt caching。

**具體進步**

- 長任務不再一直保留已看不到的子代理輸出，降低多小時 session 越跑越吃記憶體的風險。
- Runner 收到 SIGTERM 後可先服務既有 session，到期限才停放剩餘工作並離開，維護或部署時較不容易硬切正在進行的任務。
- 受控企業網路與私有 plugin registry 可以使用短效 catalog／proxy 憑證，不必把長效 token 靜態寫在設定裡。
- Remote Control 修正訊息在回合結束後消失、短暫網路問題導致登入過期、模型選擇不同步、跨 session 訊息被拒絕或 queue 滿卻假成功，以及 tasks panel 的 Stop 無效等問題。
- MCP `headersHelper` 與專案 agent 設定需要先接受資料夾 trust，helper 也不繼承 credential 環境變數，減少憑證被意外帶入的範圍。

**對工作的影響**

- 前端團隊可更穩定地讓 Claude Code 長時間跑測試、review、修正與多 session 協作，並在手機或瀏覽器上持續監看本機任務。
- 平台團隊可用私有 marketplace 分發內部技能、agent、hook 或 MCP server；正式導入要檢查 helper 命令顯示、人工同意、token scope、同源限制與 folder trust。
- 使用 self-hosted runner 時，可把優雅停機時間、proxy 憑證輪替、session 停放與重新接手寫進部署驗收，而不是只看 runner process 是否成功結束。
- `Concise` 適合降低前言與敘述量，但 code review、測試輸出、錯誤證據與未完成事項仍要明確保留，不能把「短」當成「驗收完成」。

**日期證據：** Claude Code Changelog 的 2.1.237 與 2.1.238 均標示「August 20, 2026」。

**產品狀態：** 已正式發布；Remote Control 本身仍屬 research preview，Team／Enterprise 預設需管理員啟用。

**官方來源：** [Anthropic Claude Code Changelog](https://code.claude.com/docs/en/changelog)

**官方使用參考：** [建立與分發 Plugin Marketplace](https://code.claude.com/docs/en/plugin-marketplaces)、[Remote Control](https://code.claude.com/docs/en/remote-control)

### 3. Gemini 報表新增 Google Chat 指標，可看組織與個人的採用情況

**發生什麼事**

Google Workspace 管理員現在可在 Gemini reports dashboard 查看 Google Chat 的使用指標。組織層級可追蹤活躍 Gemini 使用者與採用趨勢；個人層級則能看到哪些使用者正在 Chat 中使用 Gemini 的摘要與生成能力。

**具體進步與限制**

團隊不必再只靠問卷、教學報名或零散回報判斷 Gemini 是否真的進入 Chat 工作流。報表已可用同一個管理介面比較整體趨勢與特定使用者採用狀況，並已對 Business Starter／Standard／Plus、Enterprise Starter／Standard／Plus，以及 Google AI Pro for Education 提供。

Google 同時把部分由使用者主動觸發的 Chat 摘要互動改列為 `Active`，因此更新前後的 active user 數可能受分類口徑影響。這些數字只能說明使用行為，不能直接證明節省多少工時、摘要是否正確或決策品質有提升。

**對工作的影響**

- 設計與前端主管可找出實際採用較高的團隊，安排更針對性的 prompt、資料引用與權限教學。
- Ask Gemini in Google Chat 即將推出時，可先記錄基準值，再比較 rollout 後的使用趨勢；評估時要分開看摘要、生成、搜尋與任務建立等不同工作。
- 產品成效不能只看活躍人數，仍應搭配任務完成時間、人工修正量、錯誤案例、滿意度與資料外洩事件，避免把「有人點過」當成「已產生價值」。

**日期證據：** Google Workspace Updates 原文標示「August 20, 2026」。

**產品狀態：** 已正式提供給指定 Business、Enterprise 與 Education add-on 方案。

**官方來源：** [Google Workspace Updates：View Google Chat usage metrics in Gemini reports dashboard](https://workspaceupdates.googleblog.com/2026/08/view-google-chat-usage-metrics-in-Gemini-reports-dashboard.html)

## 對工作流的意義

今天的共同主線是「把 AI 工作流接得更完整，也讓使用與運行更可管理」。Slides 到 Vids 減少內容製作的工具切換；Claude Code 把長 session、私有擴充、自架執行與遠端協作的故障點補得更細；Gemini 報表則讓管理員看到 Chat 中的實際採用。對前端與設計團隊而言，下一步不是只看功能是否出現，而是用真實簡報、真實 coding 任務與一致的成效指標驗證：輸出有沒有更快、人工修正是否減少、權限是否清楚、長任務是否穩定。
