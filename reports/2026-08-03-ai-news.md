# 2026-08-03 AI 每日新聞

## 今日摘要

本日收錄 2 則官方消息。GitHub Copilot 企業版新增依團隊套用管理設定，讓不同職能能在共同安全底線上使用不同模型、外掛與權限；OpenAI 則公開已部署於 GPT‑Live 的低延遲語音架構，說明如何讓語音不中斷，同時在旁路執行工具與較慢的推理工作。後者是 8 月 3 日發布的工程解析，不是 GPT‑Live 產品或 API 在當日上線；官方仍標示 API 即將推出。

## 重點新聞

### 1. GitHub Copilot 企業設定可按團隊分流，模型、外掛與核准界線不再全公司一刀切

**發生什麼事**

GitHub Copilot Enterprise 與 Business 的管理員，現在可以在企業共同規則之外，替指定團隊套用更細的 Copilot 設定。企業先在內部 `.github-private` 儲存庫維持 `managed-settings.json` 作為安全底線，再以 `team-mappings.json` 將團隊對應到各自的設定檔；只有被標記為 `overridable` 的項目，團隊才可覆寫。外掛與 Marketplace 設定採加法合併，團隊只能增加企業允許的工具，不能移除企業指定項目。

**具體進步**

過去企業常在「全公司套同一組 Copilot 規則」和「所有例外都交由中央管理員處理」之間取捨。現在可讓前端、設計系統或資安團隊分別選擇合適的模型與 agent 權限，同時保留不可覆寫的企業底線。當使用者同時屬於多個團隊時，系統會合併設定，並在企業上限內採用較寬鬆的團隊值，因此團隊成員關係也必須納入權限稽核。

這套設定已適用於 Visual Studio Code、Copilot CLI、Copilot App 與 Copilot cloud agent。

**與 7 月 27 日已收錄事件的差異**

7 月 27 日的更新是把同一份企業管理設定擴及 Copilot App、cloud agent、VS Code 與 CLI，重點在不同客戶端共用規則；8 月 3 日的新功能則是在這個企業基線之下加入團隊專屬設定、可覆寫欄位與團隊對應檔。前者解決「各入口分開管理」，後者解決「不同團隊需要不同但仍受控的設定」，因此不是重複收錄。

**對工作的影響**

- 前端團隊可預先配置常用的 coding agent、外掛與模型，不必等待全公司共同調整。
- UI/UX 與設計系統團隊可加入自己的元件庫或規範工具，資安團隊則維持較嚴格的工具核准與權限模式。
- 管理員不應只檢查設定檔，也要檢查跨團隊成員關係；高風險權限應留在不可覆寫的企業層級，避免多團隊合併後意外放寬。

**產品狀態：** 已正式發布。

### 2. OpenAI 公開 GPT‑Live 低延遲架構：語音不停，工具與深度推理在旁路完成

**發生什麼事**

OpenAI 公開 GPT‑Live 的全雙工語音架構。核心做法是把即時音訊放在獨立的快速路徑，持續收聽與回應；工具呼叫、商業邏輯及較慢的前沿模型推理則以非同步方式執行，不再要求使用者每說完一句就等待完整處理。系統也能在不中斷音訊的情況下切換模型工作階段與壓縮上下文。

這篇文章描述的是已用於 ChatGPT Voice，以及新推出的桌面電腦控制與 agent 協作功能的工程架構。GPT‑Live 本身已在 7 月 8 日公開，8 月 3 日不是新的產品上線日；OpenAI 在本篇仍將 GPT‑Live API 標示為即將推出。

**具體進步**

媒體服務從 Python asyncio 改為 Go 後，新架構的第 95 百分位延遲已接近舊架構的中位數。OpenAI 將 WARP 草案與 Instant Connect 並用，把 WebRTC 連線建立移離多次往返的關鍵路徑；IETF 頁面仍明確標示 WARP 為無正式地位的 Internet-Draft，因此不應把內部成果數字當成已標準化的保證。預熱工作階段、固定連線位置與 prompt caching，則讓模型交接與工具回傳更不容易造成語音停頓。

**對工作的影響**

- 做語音 UI 時，前端可把「即時音訊狀態」與「工具／長任務狀態」拆開，避免慢查詢凍結錄音或播放。
- 介面應分別呈現暫定逐字稿、最終逐字稿、工具執行中與修正結果，讓使用者理解系統仍在聽、哪些答案尚未完成。
- 語音產品需把重連、工作階段交接、音訊恢復與背景任務失敗設計成獨立狀態，而不是只做單一 loading。
- 外部團隊目前不能把這篇文章解讀為 GPT‑Live API 已開放；現階段可先參考其媒體快路徑與 WARP 協定設計，等候正式 API 發布。

**產品狀態：** 工程架構已部署並於 8 月 3 日公開解析；GPT‑Live API 尚未發布。

## 對工作流的意義

今天兩則消息指向同一個實務方向：agent 與即時 AI 功能不能只看模型能力，還要把權限治理與互動狀態拆清楚。企業端需要讓團隊有可控的差異化設定；產品端則要讓音訊、工具、推理與錯誤恢復各自運作。對前端與 UI/UX 而言，這會直接影響權限介面、工作狀態提示、失敗處理與可觀測性設計。
