## 重點新聞

### 1. Claude Code 跨機器訊息可主動開聊，Remote Control、OAuth 與自架 runner 也更可靠

**發生什麼事**

Anthropic 在 8 月 8 日發布 Claude Code 2.1.225 與 2.1.226。`SendMessage` 現在能依 `ListAgents` 顯示的 `name [ref]`，主動向其他機器上的 Remote Control session 開啟對話，不必先等遠端 session 傳訊。已確認的遠端收件者也不會因查不到清單，被同名的本機 session 取代。

新版同時新增 gateway 花費上限警告，會顯示上限、重設時間與管理者訊息；`claude agents` 在未信任目錄也會先要求確認。可靠度修正涵蓋 headless session 的長效 `CLAUDE_CODE_OAUTH_TOKEN` 曾被短效登入 token 取代、macOS keychain 逾時後 MCP OAuth 爆發 401、跨 session 訊息無提示地停放、長對話 compaction 後無法續接、網頁 session 重連時反覆傳送事件，以及行動裝置照片需繞過額外磁碟工具等問題。

**具體進步**

跨裝置代理能主動分派與回報，而不是只能等另一端先開口；遠端任務遇到訊息送不到時，也較不會無限停放卻沒有到期或失敗提示。OAuth、長對話續接與重連事件的修正，降低無人值守工作因認證或狀態不同步而中斷的機率。

`claude self-hosted-runner` 若無法建立或寫入 `--base-dir`，現在會在啟動時直接說明錯誤，不再先註冊成功後讓每個 session 都失敗。2.1.226 另標示為錯誤與可靠度修正，但官方未公開更多細節，因此不延伸解讀。

**對工作的影響**

- 前端團隊可讓桌機、筆電與手機上的 session 主動協調建置、測試、PR 走查與長時間代理工作，降低跨裝置等待人工轉述的成本。
- 升級後仍應用未信任 repo、過期 OAuth、唯讀 base directory、大型對話 compaction、斷線重連與同名 session 做回歸測試，確認訊息實際送達且執行目錄正確。
- UI/UX 可參考明確的花費上限、workspace trust、訊息停放／到期與失敗狀態；重要遠端動作不能只顯示短暫成功 toast，應保留可追溯的收件者、狀態與錯誤原因。

**產品狀態：** 已正式發布；gateway 花費上限提示需搭配 2.1.225 gateway。

## 對工作流的意義

今天的更新重點是讓跨機器 AI coding 從「能連線」走向「能清楚判斷是否送達、是否可信、是否超額、是否真的在正確環境執行」。對前端與設計團隊而言，採用遠端 agent 時除了速度，更要把認證續期、目錄信任、成本上限、訊息狀態與錯誤恢復做成可觀察、可回歸測試的工作流。
