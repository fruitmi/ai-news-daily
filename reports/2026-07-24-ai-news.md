## 重點新聞

### 1. Claude Opus 5 正式上線，長時間 coding agent 更會驗證與修正自己的工作

Anthropic 正式推出 Claude Opus 5，主打長時間、多步驟的 coding agent 與專業工作。它已在 Claude、Claude Code、Claude Cowork 與 API 等平台提供，GitHub Copilot 也在同日開始逐步開放，開發者可直接在 Visual Studio Code、Visual Studio、Copilot CLI、cloud agent、Copilot app、GitHub 網頁、手機、JetBrains、Xcode 與 Eclipse 等入口選用。

- 具體進步：Opus 5 更傾向先找根因、建立驗證方法，再反覆修正到任務通過，而不是只改表面症狀。Anthropic 表示它在 Frontier-Bench 的表現超過 Opus 4.8 兩倍以上，CursorBench 最高設定接近 Fable 5；早期案例也包含自建 test harness、檢查桌面與手機寬度後修正 RWD 問題。這些數字與案例主要來自官方及早期合作夥伴，不能代替自家專案測試。
- 成本與平台：API 定價維持每百萬 input／output token 5／25 美元，可用 `effort` 在品質、token 與速度間調整；Fast mode 約為一般速度 2.5 倍、價格兩倍。同日 beta 也允許在對話中途更換可用工具而不破壞 prompt cache，並可在安全分類器攔截時自動切換到其他模型。
- 工作影響：前端團隊可把跨檔重構、難重現 bug、RWD 與瀏覽器驗證、測試補齊或 PR 整理交給 Opus 5，並要求它以桌面與手機實際結果作為完成條件。視覺與互動工作仍應由設計師確認品牌、無障礙與操作判斷；GitHub Copilot Business 與 Enterprise 管理員要先啟用 Opus 5 政策，使用量依供應商 API 定價計費，且模型會逐步推出。

## 對工作流的意義

今天真正值得注意的不是 benchmark 名次，而是強模型開始把「先理解、再修改、自己建立驗證、發現問題後繼續修正」做成較完整的長時間流程。前端與設計團隊可挑一個真實的跨檔 bug 或 RWD 任務，明確要求測試、桌面與手機畫面、diff 與回退方案，再比較 Opus 5 和既有模型的一次成功率、人工修正時間與成本；若只看模型分數或產出速度，仍無法證明交付品質真的提升。
