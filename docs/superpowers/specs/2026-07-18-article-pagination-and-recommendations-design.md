# 文章頁上下篇與推薦輪播設計

日期：2026-07-18

## 目標

改善文章詳情頁的閱讀寬度、標題比例與延伸閱讀體驗。文章結尾提供同日上下篇導覽，並從已有圖片的歷史文章中隨機挑選最多五篇推薦內容，同時維持純靜態網站與 GitHub Pages 部署方式。

## 已選方案

使用既有 HTML、CSS 與原生 JavaScript 實作，不引入 jQuery、Slick Carousel 或其他外部套件。

- 推薦輪播使用 CSS Scroll Snap，加上少量 JavaScript 控制左右箭頭與拖曳行為。
- 上一則與下一則只在目前報告日期內，依文章 `rank` 順序切換。
- 推薦文章每次開啟詳情頁時重新隨機挑選；同一次頁面停留期間保持順序不變。
- 圖片沿用 `getArticleImageUrl()` 與既有 TOP3 檔名規則，不新增或更改新聞 JSON schema。

未採用 Slick Carousel，因為它會增加 jQuery、CSS 與 JavaScript 依賴，也會提高本機 `file://` 預覽和 GitHub Pages 載入失敗的風險。未採用單張切換，因為它無法提供使用者要求的橫向卡片瀏覽體驗。

## 版面寬度與標題

- 移除全域 `h1 { max-width: 820px; }` 限制，不以其他選擇器覆寫或掩蓋。
- `.detail-title` 字級調整為 `clamp(1.4rem, 3vw, 2.25rem)`，維持現有行高與視覺層級。
- 保留 `.article-visual img` 的 `max-width: 1000px` 與水平置中。
- 保留先前已確認移除的文章文字區塊 `max-width: 920px`／`780px` 限制，避免重新引入窄版欄寬。

## 上一則與下一則

- 導覽列放在文章主要內容與註記之後、推薦文章之前。
- 先依 `rank` 排序目前日期的 `data.items`，再找出目前文章的相鄰項目。
- 第一篇不渲染「上一則」按鈕；最後一篇不渲染「下一則」按鈕。
- 中間文章同時顯示兩個按鈕，並附上相鄰文章標題，方便判斷目的地。
- 點擊後沿用 `article.html?date=YYYY-MM-DD&id=ARTICLE_ID` 的網址格式。
- 小螢幕改為上下排列，避免標題擠壓或按鈕超出畫面。

## 推薦文章輪播

### 資料選取

- 候選來源為目前可讀取的報告與歷史 archive 文章。
- 排除目前文章、重複 article ID，以及沒有可成功載入圖片的文章。
- 使用 Fisher–Yates 或等效無偏洗牌，從有效候選中取前五則。
- 若有效候選少於五則，顯示實際數量；若沒有有效候選，隱藏整個推薦區。
- 圖片是否有效必須經實際載入確認，不能只因推導出檔案路徑就顯示卡片。

### 卡片與互動

- 卡片使用寬扁圖片與最多兩行文章標題；整張卡片可點擊。
- 桌機約顯示三張、平板兩張、手機一張，保留下一張的適量視覺提示時不得造成頁面水平溢出。
- 支援左右箭頭、觸控滑動、滑鼠拖曳與鍵盤操作。
- 箭頭以目前可滑動方向決定 disabled 或隱藏狀態。
- 使用 `scroll-snap-type` 和 `scroll-snap-align`，滑動停止後對齊完整卡片。
- 遵守 `prefers-reduced-motion`；偏好減少動畫時使用立即定位。

## 錯誤處理與可及性

- 圖片預載失敗的候選直接略過，不顯示破圖卡片。
- archive 載入失敗時仍保留文章正文與同日上下篇，不讓推薦功能阻斷主要內容。
- 導覽與輪播按鈕使用原生 `button` 或連結，提供明確標籤、可見 focus 狀態與合理的 `aria-label`。
- 推薦圖片以文章標題作為替代文字。
- 拖曳互動不能阻止卡片的正常點擊與鍵盤導覽。

## 驗證

- 驗證文章頁內嵌 JavaScript 語法與 `git diff --check`。
- 驗證第一篇、中間篇與最後一篇的上下篇按鈕顯示狀態與連結。
- 驗證推薦結果最多五則、article ID 不重複、排除目前文章，且每張圖片均可載入。
- 驗證重新開啟文章會重新抽選，同一次渲染不會因滑動而改變順序。
- 在桌機、平板與手機寬度驗證卡片數量、拖曳、箭頭與無頁面水平溢出。
- 驗證完全沒有推薦候選、部分圖片失敗及 archive 載入失敗時的降級行為。
- 執行既有 `tools/verify-ui-behavior.ps1`，確認先前首頁與文章圖片行為沒有退步。
